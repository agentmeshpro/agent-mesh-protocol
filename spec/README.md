# AMP machine-readable specification

Everything here except this README is generated by
[`scripts/generate_spec.py`](../scripts/generate_spec.py) from the reference
implementation and the normative tables in
[`docs/WIRE-BINDING.md`](../docs/WIRE-BINDING.md). Do not edit the files by
hand: change the model or the spec text, then run
`python scripts/generate_spec.py`. CI runs `--check` and fails on drift.

| Path | Contents |
|---|---|
| `schemas/envelope.json` | `AgentMessage` envelope. Dispatches `body` to the body-type schema (or `encrypted-body.json` when `Content-Encryption` is set). |
| `schemas/body/<body_type>.json` | One schema per registered body type. |
| `schemas/agent-json.json` | `GET /.well-known/agent.json` |
| `schemas/health-response.json` | `GET /agent/health` |
| `schemas/problem-details.json` | RFC 7807 error responses |
| `schemas/encrypted-body.json` | End-to-end encrypted body (section 12.11) |
| `schemas/stream/event.json`, `schemas/stream/<event>.json` | SSE events on `GET /agent/stream` and their `data` payloads |
| `openapi.yaml` | OpenAPI 3.1 description of the HTTP binding |
| `registry/body-types.json` | Body types: schema, category, semantics, expected/valid responses, idempotency, `since` |
| `registry/headers.json` | Envelope headers and HTTP header fields |
| `registry/errors.json` | Problem `type` URNs and HTTP status |
| `registry/extensions.json` | Extension URIs (including the A2A extension) |
| `registry/stream-events.json` | Streaming event types |

All schemas are JSON Schema 2020-12. Each has a stable `$id` under
`https://github.com/CatlystAI/agent-mesh-protocol/spec/schemas/`, and
cross-file `$ref`s are relative to it. Load them into one registry keyed by
`$id` (for example with Python `referencing`, Ajv `addSchema`, or Go
`jsonschema.Compiler.AddResource`).

`since` values below 1.0.0 are the `ampro` releases that introduced a name
before the protocol 1.0.0 freeze (see `CHANGELOG.md`).

Rules that JSON Schema cannot express (cross-field checks and signatures)
are listed in each schema's `x-amp-constraints`. Validate those in code.
The test vectors in [`tests/vectors/`](../tests/vectors/) cover them.

To test a running implementation over HTTP, use the black-box suite:
`ampro-conformance --url https://agent.example.com` ([docs/CONFORMANCE.md](../docs/CONFORMANCE.md)).
How the spec changes is described in [GOVERNANCE.md](../GOVERNANCE.md), and
how to extend it without forking is in [docs/EXTENSIONS.md](../docs/EXTENSIONS.md).
